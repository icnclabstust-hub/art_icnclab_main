# RAG 新架構：完成度、架構缺口與待訂項目總表（2026-09-21）

> 用途：彙整「新架構圖」目前做到哪、還差哪些區塊，以及所有尚未決定的事項，供使用者與指導老師一次看完。
> 資料來源：`docs/decision-log.md`、三份 Phase 設計文件、2026-09-21 對程式碼與資料庫的查證。
> 狀態說明：本表中的「待訂項目」**皆尚未決定**；建議欄只是提案，不是決定。GD 評估表簽核欄依 `CLAUDE.md` R5 由使用者／老師填寫，AI 不代填。

## 一、摘要

- **資料層與資料同步這一半已完成並實跑驗證**；**回答品質把關與回饋迴圈這一半只完成設計，尚無實作**。
- 待訂項目共 **19 項**（Phase 3：6 項；Phase 4／5 與另案：13 項），另有 **6 項維運待辦**。
- 卡點是一條鏈：**標註人力、法規與告知文字、老師核可 → Phase 3 黃金測試集 → Phase 4／5 的門檻校準與路由比較**。這幾項解決前，Phase 3–5 都不進入實作（Tier B，須老師核可）。

## 五、建議的處理順序

1. **先解卡點**（可並行）：指定標註人選（A1）、請老師／單位確認法規與告知文字（A4）、補簽評估表（A5）。
2. **Phase 3**：老師核可後實作；先關 `BIZ_LOGGING`，建黃金測試集與基準，再把量測加進夜間流程。
3. **Phase 4**：影子模式累積資料 → 用黃金集校準門檻 → 分路由逐步啟用。
4. **Phase 5**：先做系統級 RRF，再依量測決定是否加重排與 Router 權重。
5. **另案**（B10–B13）可獨立排程，不阻擋主線。
