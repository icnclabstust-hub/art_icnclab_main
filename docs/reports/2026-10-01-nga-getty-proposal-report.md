## 二、為什麼要做

1. **Yale 已移除**（9/23，來源端 403）。catalog 內 289 份已軟刪除、檢索庫已撤出，Neo4j 節點將於 10/23 起自動清除，不需再處理；但系統少了一個美術館來源。
2. **來源條件**：不需 API 金鑰（符合金鑰管理規則）、授權寫進論文無爭議。NGA 為 **CC0**，最乾淨。
3. **順帶處理兩個已觀測到的品質缺陷**：
   - 藝術家重複：圖譜內 **157 組、562 個節點**疑似同一人被拆開（例：Rembrandt 分成 6 個）。NGA 會再帶進約 2.8 萬位藝術家，不處理會更嚴重。
   - 中文查詢召回差：黃金集候選表實測，以中文名查維梅爾、委拉斯奎茲，6 個檢索策略都找不到館藏作品。

## 三、做什麼、不做什麼

**本輪做**

| 項目 | 內容 | 授權 |
|---|---|---|
| NGA 館藏 | 146,099 件，含來源史；每晚增量同步 | CC0-1.0 |
| Getty ULAN | 以固定編號整併同一藝術家的多個節點（加連線、不刪節點，可撤回） | ODC-By 1.0 |
| Getty AAT | 以官方繁體中文詞彙擴充查詢翻譯詞典，**人工審核後才生效** | ODC-By 1.0 |

**本輪不做（理由見設計文件 §2）**：SMK 等其他館、圖片、Getty 地名（TGN）、師承關係入圖譜、Harvard 重複實作清理、Neo4j 萬筆分片備份。

## 四、成本與時程

- **工時**：約 5.5 人日，另加人工審核 0.5～1 人日（ULAN 疑義名單、AAT 候選詞）。
- **首次載入**：嵌入約 14.6～16.2 萬個文字塊，**嵌入實測約 1.4 小時（bge-m3 32.2 chunk／秒，2026-10-01 以 NGA 真實文字抽樣量測），含寫入三庫估計共 2～3 小時**，在夜間流程以外分批執行。
- **每晚流程**：NGA 平日變動約 266 件，預估多 5～10 分鐘；9 月單日最高 2,708 件，峰值日嵌入約 1.6 分鐘（實測）。
- **不新增**任何套件、服務、port 或排程。

## 五、風險與對策

| 風險 | 對策 |
|---|---|
| 首次載入時間長，與線上查詢搶 GPU | 夜間流程以外分批執行，每批驗證一致性後再繼續 |
| 版畫、攝影數量大，可能稀釋檢索結果 | 黃金集基準出來後檢查，必要時調整權重 |
| 藝術家誤合併 | 只有「NGA 自帶編號」與「名稱＋生卒年唯一吻合」兩級自動處理，其餘人工審核；全部可撤回 |
| 中文術語誤譯（實測 Realism → 唯實論、bronze → 古銅色） | 限定類別產生候選、人工審核後才寫入詞典 |
| Elasticsearch 記憶體不足（目前未設上限、佔 12.3 GB） | 資料量增加前先設定 heap 為 2 GB（需系統管理員權限） |

## 六、回滾

NGA 資料可整批撤出；藝術家整併刪除連線即恢復；詞典回復 git 前一版；每晚流程移除一行即可。**沒有不可逆的動作。**

## 七、與黃金集的先後

使用者決定：**先接 NGA，再重產黃金集候選表並標註**。好處是正解會包含 NGA 的巴洛克作品（NGA 標為巴洛克風格者 970 件，含 Rembrandt 480 件、Rubens 251 件、Vermeer 12 件）；代價是標註要等 NGA 上線。
