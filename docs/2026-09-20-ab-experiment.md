# 兩項修正的 A/B 實驗設計（2026-09-20）

> 性質：實驗設計 + 待填結果表。對應輸入：使用者回報的兩項修正
> （E1 `Artist.sources`、E2 Neo4j 綁定）。
> **本 session 無法觸及現場**，所以本文件只設計與提供指令，數字由 `scripts/ab-experiment.sh` 在機器上產生後回填。
> 執行：`bash scripts/ab-experiment.sh discover` → `accuracy` → `probe` → `binding`。

## 0. 這份實驗要回答什麼

兩項修正各有兩個做法，用**同一題**當共同探針：

```
題目（固定不變）：
  梵谷（Vincent van Gogh）現存作品分別來自哪些館藏來源？請完整列出全部來源。
```

| | 方法甲 | 方法乙 | 方法丙（僅機制對照） |
|---|---|---|---|
| **E1 藝術家來源** | `Artist.source` 單值 | `Artist.sources` 推導清單 | — |
| **E2 Neo4j 綁定** | `0.0.0.0` + `preferIPv4Stack` | `127.0.0.1` + `preferIPv4Stack` | `0.0.0.0`，**不加** `preferIPv4Stack` |

2（綁定）× 2（來源欄位）= 4 格，每格問同一題。丙格只跑連線測試，不跑題目。

**為什麼挑這一題**：它是唯一能同時打到兩項修正的題目。

- 打到 E2：回答需要查圖，圖連不上就沒有答案——連線是這題的前置條件。
- 打到 E1：梵谷橫跨 Cleveland / Yale / Europeana **三個**來源，單值欄位結構上就裝不下；
  而且他的舊 `source` 是 `met_museum`，而他已無任何現存 Met 作品——
  單值不只是「少講兩個」，是**講了一個錯的**。這兩種錯誤形態（漏 + 錯）一題全包。

## 1. 基準（ground truth）怎麼定

```cypher
MATCH (a:Artist)-[r:CREATED]->(w:Artwork)
WHERE r.expired_at IS NULL            // 關係未到期
  AND w.deleted_at IS NULL            // 作品未軟刪除
  AND coalesce(w.is_deleted,false) = false
WITH a, collect(DISTINCT w.source) AS truth
```

標籤與屬性名**請先用 `discover` 子命令核對**，不要照抄。理由見 §5.1。

### 1.1 這個基準有一個循環論證，必須先講清楚

乙（`Artist.sources`）的定義**就是**上面這條規則。拿同一條規則當基準，乙的 F1 必然是 1.0000——
那不是「乙比較準」，那是「乙照定義算對了」。所以這場實驗真正測到的是：

| 指標 | 實際在測什麼 | 有沒有意義 |
|---|---|---|
| 乙的 F1 | 儲存欄位與即時推導**是否同步**（有沒有漏重算） | 有。這正是「每批事件後重算」這個機制的驗收點 |
| 甲的 F1 | 單值表示法**能表達多少** | 有。上限 = 1/每人來源數，與資料品質無關 |
| 「誰的規則比較對」 | **沒測到** | 要另外驗，見下 |

補救辦法寫進 `accuracy` 的 1d 段：抽 20 筆梵谷的作品，印出 `w.source` 與它的 URL／識別碼，
人工比對來源標記是否與實際出處相符。**作品層的 `source` 由匯入路徑寫入，與藝術家層無關**，
所以這一步是獨立的。這 20 筆對不上，上面所有準確率數字都不用看，先修匯入路徑。

### 1.2 N=1 不是準確率

同一題只有一位藝術家，算不出準確率，只能算「這一題答對沒有」。
所以 `accuracy` 另外跑一次**母體**（約 2,915 位）的 micro-P / micro-R / F1。
結果表裡這兩者分開列，不要混講。

### 2.1 撤回 P2：端到端那一段分不出 E1 的甲乙

檢索端的圖查詢**不讀** `Artist.source`，梵谷的來源是查詢時從作品層走圖推導出來的。
既然沒有任何消費端讀那個欄位，甲乙在同一題上會輸出**完全相同**的答案——
端到端那一段對 E1 沒有鑑別力，P2 不成立，撤回。

**E1 只能在資料層判定**（§1 的母體 micro-P/R/F1 + 抽樣）。同一題在 E1 這邊的角色退為
「確認欄位改動沒有把原本會動的查詢弄壞」，不是準確率的度量。

這也是 E1 的實際價值所在：它現在**不影響任何答案**，改的是後續消費端能不能信任這個欄位。
`discover` 的 0e 段會把「目前誰在讀這兩個欄位」列出來——若那份清單是空的，
E1 的收益全部在未來，判定時要照這個前提寫，不要宣稱改善了檢索品質。

### 2.2 E1 的結構上限（先算清楚，免得把功勞算錯地方）

依實測分布 2,842×1 + 59×2 + 11×3 + 2×4 + 1×5 = 3,006 個「藝術家–來源」配對：

| 狀態 | micro-R | 說明 |
|---|---|---|
| 甲 現況（973 空值） | 1942/3006 = 0.646 | — |
| 甲 補完舊資料後 | 2915/3006 = 0.970 | 單值表示法的**理論上限** |
| 乙 | 1.0 | — |

單值的結構損失只有 **3%**，因為 97.5% 的藝術家只有一個來源。
33% 那個缺口來自「Europeana 寫入路徑沒設」，與表示法無關，補寫入路徑就解決。

所以採用乙的理由是**推導 + 每批重算這個不變式**（過時值自動消失），
不是「清單比單值準」。這兩個理由會導向不同的驗收重點：前者要驗 1c 的反向檢查，後者只看 F1。

P4 是整組實驗裡唯一能證明**因果**的一格：甲乙都成功只能說「兩法都可行」，
只有丙失敗才能說「成因是雙堆疊 socket，不是綁定位址」。
丙這一格成本只有一次改設定 + 重啟，**建議不要省**。

## 3. 指標與判定門檻

### E1（準確率為主）

| 指標 | 甲門檻 | 乙門檻 |
|---|---|---|
| 這一題：命中全部真實來源 | — | 必須全中 |
| 這一題：未出現過時來源 | — | 必須沒有（硬指標，不需人工判斷） |
| 母體 micro-R | 記錄即可 | ≥ 0.999 |
| 空值數 | 記錄即可 | 必須 = 0 |
| 反向檢查（作品全下架者仍有 sources） | — | 必須 = 0 |
| 5 次重跑答案一致 | — | ≥ 4/5，否則是 LLM 不穩，不是欄位問題 |

### E2（可行性為主，「準確率」在此讀作「成功率」）

| 指標 | 門檻 | 說明 |
|---|---|---|
| socket 家族 | 必須是純 IPv4 | `tcp 0.0.0.0:*` 或 `tcp 127.0.0.1:*`；出現 `[::]` 即為失敗態 |
| Windows `localhost:7474` → 200 | 20/20 | — |
| Windows **Bolt 交握**（非只有 TCP） | 20/20 | 前次結論只測到 TCP 連得上就停了，那**證明不了 Neo4j 可用** |
| 跨 WSL 重啟後仍成立 | 3/3 次重啟 | WSL IP 會變，這格分辨「真的靠 localhost 轉發」還是「剛好連到 IP」 |
| 暴露面 | 乙應「連不上」 | 甲會讓同網段主機連得到 7474/7687 |
| 同一題答案與另一綁定一致 | 必須一致 | 對應 P6 |

## 4. 執行順序

```
步驟 0  discover    唯讀。核對 schema、服務狀態、目前綁定。對不上就先改環境變數，不要硬跑。
步驟 1  accuracy    唯讀。E1 甲乙 + 母體 + 抽樣 + 同一題 ×5。此時綁定維持現狀。
步驟 2  probe       唯讀。記下目前綁定的成功率，當作對照基線。
步驟 3  binding --method A → 重啟 Neo4j → probe → 同一題 ×1
步驟 4  binding --method B → 重啟 Neo4j → probe → 同一題 ×1
步驟 5  binding --method C → 重啟 Neo4j → probe（預期失敗，這格是重點）
步驟 6  restore     還原設定檔
```

重啟 Neo4j 時**務必確認重啟的是哪一個實例**。這台機器上系統 `neo4j.service` 走 systemd、
專案實例走 `Start-NativeServices.ps1` 的 `neo4j console`（問題登錄表 B1）。
弄錯會再製造一次雙實例互搶，實驗結果就全廢了。腳本刻意**不替你決定**重啟方式，原因在此。

## 5. 已知的效度威脅

### 5.1 schema 名稱猜錯會產生「看起來很正常的錯數字」

Cypher 對不存在的屬性回傳 `null`，不報錯。若 `expired_at` 實際叫 `valid_to`，
那麼 `r.expired_at IS NULL` 對每一列都成立 → 「未到期」條件變成恆真 →
已到期的關係被算進基準 → 數字照印，但是錯的。

**這是本實驗最可能的無聲誤差來源。** 所以步驟 0 不可略過，
`discover` 會把 `db.propertyKeys()` 的實際內容印出來逐項對照。

### 5.2 關鍵字評分是粗評

端到端答案用關鍵字命中評分。「答案正確」以人工複核為準。
但「出現過時來源」那一格是硬指標——出現即為錯答，不需人工判斷。

### 5.3 LLM 不確定性

同一題跑 5 次。若 5 次答案不一致，先解決穩定度再比較欄位，否則量到的是取樣雜訊。
檢索參數（temperature、top-k）在 4 格之間必須一致，否則不是對照實驗。

### 5.4 WSL 網路模式是共變項

`.wslconfig` 若設 `networkingMode=mirrored`，localhost 是真的共用，
兩種綁定法可能都會通，結論**不能外推**到 NAT 模式的機器。`probe` 會把這格印出來，請記進結果表。

### 5.5 E2 的設定檔不在版控內

設定檔在 Neo4j 安裝目錄，不在 repo 裡。還原點是同目錄的 `neo4j.conf.bak-*`。
**重裝 Neo4j 要重新套用。** 這是這個修法的固有成本，不是實驗的瑕疵，
但要記進結果表——它是「甲乙兩法都有、而其他解法未必有」的長期維護債。

## 7. 對兩項既有結論的再檢視

這兩點不是推翻，是指出「已驗到哪裡」與「還沒驗到哪裡」：

1. **E2 的「7687 連得通」目前只到 TCP 層。** TCP 連得上只代表有人在該埠 listen，
   不代表 Bolt 交握會成功、更不代表認證通得過。`probe` 的 2d 段補上真正的查詢驗證，
   取代「還沒實際開 Neo4j Browser 登入」那個缺口。

2. **綁定位址與 `preferIPv4Stack` 是兩件正交的事。**
   依雙堆疊假說，真正讓 WSL 轉發器認得的是 `preferIPv4Stack`（把 socket 變成純 IPv4），
   綁 `0.0.0.0` 或 `127.0.0.1` 改變的是**暴露面**，不是轉發行為。
   若此假說成立，`0.0.0.0` 單獨使用（丙）會失敗——這是丙格存在的唯一理由。
   在丙格跑出來之前，「綁 0.0.0.0 可以解決問題」這個說法**未經檢定**。

3. **E1 的「2,915 位全部有 sources、0 位為空」是自我一致性檢查，不是準確率。**
   它證明欄位填滿了，沒證明填的值對。準確率要靠 §1.1 的抽樣那一步。
