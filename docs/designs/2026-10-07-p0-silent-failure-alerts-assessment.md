## 三、現況調查結論與作法

- 既有可重用：`ingest.alerts.open_or_update／resolve`（同指標同路由只留一筆、恢復自動結案）、每日告警彙總、`diagnose.py`。
- 為何不看攝取結果：攝取找不到新檔會退回讀舊檔，10-03 MET 失敗時攝取顯示「未變 744」，失敗被掩蓋；必須看爬蟲自己的輸出目錄。
- 作法：
  - `ingest check-crawl`：每支爬蟲跑完後比對其輸出目錄，本次無 ≥1 KB 新檔 → `crawl_output` critical；新檔小於上次一半 → warning；正常 → 結案。不解析檔案內容（九支爬蟲格式不同）。
  - `ingest check-gap`：每日流程開始時，距上一份每日 log 超過 26 小時 → `pipeline_gap` warning（事後留紀錄）。
  - `diagnose.py`：最新每日 log 超過 26 小時即顯示警告（排程完全沒跑時唯一看得到的地方）。
- 實作時順帶修正：`diagnose.py` 找 log 的檔名樣式寫錯（`crawl_*.log`，實際為 `catalog_crawl_*.log`），**每日 log 從未被掃描**；修正後揭露知識庫 `403`／`429` 樣式為裸數字，會誤中時間戳毫秒，已改為只比對 HTTP 狀態碼。
- □ 調查後結論為「不需開發」
