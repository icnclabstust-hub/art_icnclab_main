# 設計文件：分層標示的回答——有來源的回答＋以推理模式產生的模型補充

> 狀態：**草案**（GD 步驟 3）。風險 Tier：**B**（改 art_icnclab RAG 服務的回答格式與生成流程）——**實作前須老師核可**。
> 步驟 1、2 已在 2026-10-08 對話中完成，使用者決定見 §1；本設計**修訂** Phase 4 設計（`2026-09-21-phase4-evidence-refusal-faithfulness-fuzzy.md`）中「證據不足 → 拒答」的分支。
> 評估表：`2026-10-08-layered-answer-assessment.md`。

## 1. 背景與問題

使用者 2026-10-08 決定：
- 論文核心為「一套一致、可驗證的 RAG 架構」，驗證**忠實度**與**準確性**，並分析**提升空間**。
- 使用者為研究者與學生（藝術史知識普及）。
- **找不到來源時，由 LLM 以推理模式（思考鏈）回答**，不拒答；採「分層標示」呈現。
- 8/15 的 24 組合評測結果**不用於論文**（該批題目的檢索精確率近 0，比較的是 LLM 本身知識，見 decision-log 2026-10-08）。

這與現行規格兩條衝突，須正式變更：

| 條文 | 現行 | 變更為 |
|---|---|---|
| GRD-01（決策 B1） | 無證據時**預設拒答** | 預設**分層標示後回答**；拒答保留為設定選項 |
| GEN-04 | `citations[]` 為空時不得輸出答案 | 可只輸出「模型補充」層，但必須明確標示且不得帶引用 |

**核心張力**：允許模型自行回答後，使用者分不出哪句有出處——直接抵觸「可驗證」。本設計以分層化解：**每一句話不是有引用，就是被明確標示為沒有出處**。

## 2. 目標與非目標

- 目標：
  1. 回答分兩層：**【依據館藏與文獻】**（逐句附引用）與 **【模型補充說明，未經資料庫來源驗證】**（推理模式產生）。
  2. 有來源層只能使用檢索來源；模型補充只回答有來源層答不了的部分，不重複、不冒充出處。
  3. 回應帶 `risk_flags[]`（GEN-03），可程式判讀哪些內容未經來源驗證。
  4. 模型補充的題目進入每週複審（沿用 EVL-15～17 的佇列與流程），作為「資料缺漏」回饋採集層（流程 E-4）。
  5. 定義論文指標「**可驗證性**」：每句有引用或被標示的比例（目標 100%）。
- 非目標：
  - 證據門檻 K 的校準（仍為 Phase 4 GRD-02～05，本設計只預留觸發點）。
  - 精篩 NLI（GRD-07）、概念語料（使用者決定先保留）、長文件檢索（另案）。
  - 改動檢索；不影響巴洛克文件層級基準（EVL-05）。

## 3. 現況與重用

| 既有件 | 本設計如何用 |
|---|---|
| `guard_coarse.check_answer`（錨點比對，GRD-06） | 檢查有來源層每句是否有來源支撐；未通過者加 `risk_flags`，不改寫內容 |
| `citations[]`（GEN-02） | 有來源層的 `[n]` 對應引用；模型補充層不得出現 `[n]` |
| `_no_think`／`RAG_NO_THINK_MODELS` | 有來源層維持關閉思考（快）；模型補充層開啟思考（使用者指定推理模式） |
| Open WebUI 對 `<think>` 區塊的呈現 | 推理過程以可收合區塊呈現（是否顯示見 §9） |
| `eval.guard_shadow`、影子模式（GRD-08） | 上線初期只記錄分層結果，不改變回應，累積後再切換 |
| 拒答佇列設計（EVL-15，表尚未建） | 改為「模型補充佇列」：存問題、缺口、時間；**不存 user_id**（EVL-15a） |

## 4. 方案比較

| | 方案 A：一次生成＋提示分段 | 方案 B：兩階段、條件觸發（**選定**） | 方案 C：自由生成後逐句分類 |
|---|---|---|---|
| 做法 | 單次提示要求模型自行分成兩段 | ① 只依來源回答，並列出「來源答不了的子問題」；② 若有缺口，才以推理模式只回答這些缺口 | 模型自由回答，回傳前逐句判斷有無來源支撐，再分到兩層 |
| 可驗證性 | 依賴模型自律，**8B 模型常把自身知識混進有來源段**（10-03／10-08 已觀察到） | **由流程保證**：有來源層的提示只給來源；模型補充層是另一次呼叫 | 依賴逐句判斷的準確度（10-03 實測 LLM 裁判召回約 50%） |
| 延遲 | 1 次生成 | 有足夠來源時 1 次；有缺口時 2 次（第 2 次含推理，較慢） | 1 次生成＋每句一次模型判斷（違反 GRD-06b「同步粗篩不得呼叫模型」） |
| 成本 | 約 40 行 | 約 150 行＋測試 | 約 120 行，且需修改 GRD-06b |
| 風險 | 可驗證性無法保證，與論文主軸衝突 | 第 ① 階段列出的缺口可能不準（漏列或多列） | 違反規格；判斷錯誤會把幻覺放進有來源層 |

**選定 B**：論文主軸是「可驗證」，必須由架構保證而非仰賴模型自律。條件觸發讓「館藏有資料」的常見問題維持單次生成的速度，只有理論題等缺口才付出推理成本。缺口判斷不準的風險，以 §7 的驗收題組量測，並在 Phase 4 證據門檻（GRD-02）校準後，改由「證據分數＋缺口清單」共同觸發。

## 5. 系統設計

### 5.1 流程
```
檢索（不變） → ① 有來源層生成（思考關閉，只給來源）
                  輸出：answer_sourced（每句帶 [n]）＋ gaps[]（來源答不了的子問題）
               → 粗篩（GRD-06）檢查 answer_sourced，未通過的句子記入 risk_flags
               → 若 gaps 非空或 citations 為空：
                  ② 模型補充層生成（推理模式，不給來源，只回答 gaps；禁止 [n]）
               → 組合回應；模型補充題目寫入複審佇列（不存 user_id）
```

### 5.2 回應格式（新增欄位，不改既有欄位）
- `answer`：組合後的完整文字（Open WebUI 直接顯示），兩層各有固定標題；推理過程依 §9 決定是否以 `<think>` 收合區塊附上。
- `answer_layers`：`{"sourced": str, "model_knowledge": str | null, "gaps": [str]}`
- `risk_flags[]`：`model_knowledge`（有模型補充層）、`sourced_unsupported:<句序>`（有來源層未通過粗篩）、`no_sources`（完全無引用）。
- `citations[]`：只對應有來源層。

### 5.3 設定（集中登記於 `.env.example`，SYS-08-T）
- `ANSWER_MODE=layered|refuse`（預設 `layered`；`refuse` 即原 GRD-01 行為）
- `MODEL_KNOWLEDGE_MODEL`（模型補充層使用的推理模型，待 §9 決定）
- `SHOW_REASONING=collapsed|hidden`
- `LAYERED_SHADOW=true`（影子期：照常回傳原格式，只記錄分層結果）

### 5.4 規格變更（核可後寫入規格書）
- **GRD-01**：無檢索支撐時預設分層標示回答（`ANSWER_MODE=layered`）；`refuse` 為可選。
- **GEN-03**：`risk_flags[]` 改為**必做**，值域見 §5.2。
- **GEN-04**：改為「`citations[]` 為空時，只能輸出模型補充層，且必須帶 `risk_flags: no_sources, model_knowledge`」。
- **新增 GEN-05**（分層格式）、**GEN-06**（模型補充層使用推理模式，有來源層不使用）。
- **新增 EVL 指標「可驗證性」**：每句有引用或被標示的比例；**EVL-15** 佇列擴及模型補充題目。
- **不變**：GRD-09（防護元件出錯仍拒答）、GRD-06b（同步粗篩不呼叫模型）。

### 5.5 錯誤處理
- ① 失敗 → 沿用現行錯誤處理；② 失敗 → 只回有來源層並加 `risk_flags: model_knowledge_failed`，不影響有來源層。
- ① 的缺口清單格式解析失敗 → 視為無缺口（保守：不多產生未經驗證的內容），記 warning。

## 6. 安全與隱私考量
- 模型補充層可能幻覺：以固定標題與 `risk_flags` 明確告知，不出現引用編號，避免被誤認為有出處。
- 推理過程可能複述使用者問題：不寫入稽核 log（S-15 沿用）；複審佇列只存問題與缺口，不存 `user_id`（EVL-15a，`BIZ_LOGGING` 仍鎖定關閉）。
- 提示注入：來源內容仍視為資料；模型補充層不接觸來源，降低注入面。

## 7. 測試策略
- 單元：缺口清單解析、兩層組合、`risk_flags` 規則、有來源層 `[n]` 與 citations 對應、模型補充層不得含 `[n]`。
- 整合：拋棄式 DB 驗證複審佇列寫入且無 user_id；影子模式下回應與現行一致。
- 驗收（兩份題庫）：
  - **可驗證性 = 100%**（每句有引用或位於標示層）。
  - 巴洛克 15 題：有來源層忠實度不低於現況；事實題準確性不退步；不應出現模型補充層的題目（資料充足）比例 ≥ 80%。
  - 15 題理論題：準確性（A／B 主張覆蓋）高於現況 6%；模型補充層的錯誤主張數記錄於論文（不設門檻）。
  - 延遲：無缺口路徑 P95 不高於現況 +10%；有缺口路徑另行報告。
