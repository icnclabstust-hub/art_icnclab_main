# 第 2 層改動實驗評估表：回答串流顯示（整句送出、狀態列、並行預載）

> 範本：`docs/templates/LAYER2_EXPERIMENT_ASSESSMENT.md`；設計 `docs/designs/2026-10-14-streaming-response.md`（使用者 10-14 確認）。
> 風險 Tier B（改變 Open WebUI 使用者路徑），**須指導老師核可才可上 8001 與 Open WebUI**。
> 前提：與 CPU Ollama 分離架構（`2026-10-14-cpu-ollama-split-experiment.md`）一起上線；本表量測皆在分離架構下。

## 一、變更描述
- 後端新增 `POST /api/v1/query/stream`（NDJSON：`meta` →（`waiting`／`thinking`）→ `delta`… → `done`；錯誤 `error`）。`/api/v1/query` 對外行為不變（共用 `_prepare_query`／`_finish_query`）。
- 送出單位：第一段可在逗號處提早送（≥ 8 字），之後整句；每句經 `sentence_hook` 檢查點（目前不改內容，預留守門員攔截 #15、分層回答 #12）。
- 等待回饋：模型載入中每 3 秒 `waiting`、思考中（deepseek `<think>`、gemma `thinking` 欄位）每 3 秒 `thinking`；pipe 顯示於狀態列。
- 4 支 system pipe（hybrid／vector／fulltext／graph）改 async＋httpx 串流，閥值 `STREAM`（預設開）；端點 404 或連線失敗自動退回 `/query`；選單標示「Qwen3 14B／Gemma 4 12B（深度思考·較慢）」。
- `GENERATION_PRELOAD`（預設關）：收到請求即預載生成模型。
- 舊策略 pipe（legacy 4 支）不變（仍為非串流）。

## 二、假設
- 預期變好：使用者等待第一個字的時間（8B：完整回答 7～16 秒 → 首句約 2～3 秒）。
- 可能變差：①第一句多等一個子句（約 0.5 秒）；②守門員影子模式與答案快取改在串流結束後執行（行為同前，時間點延後）；③Open WebUI 非串流 API 呼叫（8080 評估腳本）需由 Open WebUI 拼回完整回答——已查證 Open WebUI 0.11 `get_message_content` 支援 AsyncGenerator。

### 3.2 首句時間（E19，目標：已載入 ≤ 3 秒、換載 ≤ 10 秒）
| 模型 | 已載入 首句 | 換載 首句 | 首次回饋（狀態列或首句）最大 | 完整回答（熱） |
|---|---|---|---|---|
| qwen3:8b | **1.5～2.3 秒** ✅ | 12.0 秒 ❌ | 3.7 秒 | 10.8～12.1 秒 |
| llama3.1:8b | 2.5～4.3 秒（中位 3.4）⚠️ | —（前一測試已載入） | 4.3 秒 | 5.7～9.6 秒 |
| qwen3:14b | 3.1～5.7 秒 | 25.4 秒 | 5.7 秒 | 47.6～73.5 秒 |
| deepseek-r1:8b（先思考） | 7.5～9.8 秒 | 17.8 秒 | **3.7 秒** | 11.2～16.7 秒 |
| gemma4:12b（先思考＋部分 CPU） | 45.5～83.5 秒 | 66.6 秒 | **3.8 秒** | 61.5～95.3 秒 |

- llama 為第一個測的模型，4 題翻譯皆未快取（qwen3:1.7b 每題 1～2.8 秒），是已載入首句 > 3 秒的主因；後測模型命中翻譯快取。
- 換載首句 > 10 秒：GPU 換載 5 GB 模型（磁碟重讀）約 9～10 秒，屬硬體限制。
- deepseek／gemma 的思考（不顯示）使首句延後，但每 3 秒的「準備中／思考中」狀態使首次回饋 ≤ 3.8 秒。
- qwen3 系列已預設關閉思考（`RAG_NO_THINK_MODELS=qwen3`），故 qwen3:14b 首句快於 deepseek／gemma。

### 3.3 冷啟動拆解（E17）
- 檢索（含翻譯快取）0.7 秒內完成；其餘 9.5～10 秒為 GPU 換載模型（卸載＋從磁碟載入 5 GB）＋生成。
- 並行預載無明顯差異（開 10.0～11.4 秒、關 10.6～11.3 秒）：翻譯已快取時沒有可重疊的時間；僅在翻譯未快取時可省 1～3 秒。
- 模型檔 33 GB 超出 WSL 22 GB 記憶體，每次換載需重讀磁碟——屬硬體限制（同 decision-log 10-14「硬體限制」）。
- E20：加上換模型主動卸載（`GENERATION_SWITCH_UNLOAD=1`），換載首句平均 18.6 → 13.5 秒，llama／qwen3:8b 9.9～11.2 秒；進行中請求不受影響。建議與串流一起上線。

## 五、風險與回退
- 關閉：Open WebUI 管理介面把 pipe 閥值 `STREAM` 關閉即回現行非串流（不需重啟）；後端端點可留著（不影響 `/query`）。
- 已知風險：①deepseek-r1／gemma4:12b／qwen3:14b 需先思考，首句仍慢（以狀態列顯示進度）；②換載模型首句約 10～11 秒（硬體限制）；③legacy pipe 未串流。
- 上線後驗證（8080）：使用者路徑實測首句時間與狀態列，8080 非串流評估腳本照常可跑。
